# 世界地图与副本系统设计

## 目标

建立一张唯一且固定的世界地图：这个世界由多个国家组成，国家下设城市，城市提供若干副本。玩家不选择或切换世界。每个副本有独立难度、路线和事件池；探索途中会遭遇野生精灵对战，胜利后获得宠物经验，作为主要刷级玩法。

首期采用单人探索，每位玩家带当前宠物进入副本。组队、多人副本、捕捉精灵、装备掉落、赛季榜和跨平台匹配暂不纳入首期。

## 背景故事框架

故事发生在艾洛恩大陆。数百年前的“星核坠落”撕开大地，散落的源晶改变了森林、沙海、海底与火山，也形成了被称为“副本”的异变区域。野生精灵在源晶附近获得力量，部分变得躁动。各国成立冒险者公会，委托冒险者探索副本、安抚或击败失控精灵，并查明星核坠落是否正在重演。

每个国家有自己的故事线和事件主题，但都会留下与星核碎片有关的线索。玩家从云岚王国的边境事件开始，逐步前往北境联邦和赤曜帝国；通关副本既推进宠物养成，也解锁新的城市、事件与主线线索。叙事通过地点描述、事件分支和首领对话承载，不把剧情写入战斗结算代码。

## 世界层级与解锁

```text
世界
└── 国家
    └── 城市
        └── 副本
            └── 难度
                └── 关卡与事件
```

- 世界是唯一的静态根节点；国家、城市、副本和难度使用稳定 ID，显示名、描述、地理关系和解锁条件放在静态资源中。
- 地图是可浏览的内容树，不要求玩家维护一个会移动的实时坐标。玩家从已开放城市选择副本进入。
- 所有玩家都从这张地图上的起始国家和城市开始。清除指定副本后开放同一世界内的后续城市或国家；解锁条件引用副本通关记录，不依赖显示名称。
- 同一副本可以提供普通、困难、噩梦等难度。各难度配置推荐宠物等级、敌人等级系数、事件权重、通关经验加成和最终首领，不用代码分支区分每个副本。
- 首期每名玩家同一时间只能有一个未完成的副本探索；不同聊天群发出的命令仍操作同一份平台玩家进度。

地图示例：

| 国家 | 城市 | 副本示例 | 解锁方向 |
| --- | --- | --- | --- |
| 云岚王国 | 青溪城 | 回声林地（简单 / 普通） | 起始区域 |
| 云岚王国 | 赤砂城 | 风蚀峡谷（普通 / 困难） | 通关回声林地普通 |
| 北境联邦 | 白港城 | 沉船回廊（普通 / 困难） | 通关风蚀峡谷困难 |
| 赤曜帝国 | 灰烬城 | 炉心遗迹（困难 / 噩梦） | 通关沉船回廊困难 |

## 副本路线与事件

副本是一段有限长度的路线，由多个关卡构成。每个关卡配置事件池和权重，路线末尾固定放置首领战。资源只描述事件类型、文本、条件与效果，不包含可执行代码。

首期事件类型：

| 类型 | 结果 |
| --- | --- |
| `story` | 展示地点背景和线索，不改动角色数据 |
| `spirit_battle` | 与野生精灵对战，胜利后授予宠物经验 |
| `rest` | 恢复本次探索中宠物的部分生命和魔力 |
| `choice` | 展示有限选项，例如安全路线或高风险捷径；选择结果由静态效果定义 |
| `hazard` | 陷阱或环境事件，按副本配置扣除探索中的宠物生命、消耗资源或转入战斗 |
| `treasure` | 发放已有货币或副本通关标记，不在首期新增可交易掉落物系统 |
| `boss` | 每个难度的固定首领精灵战，胜利后完成副本并开放解锁内容 |

每个副本定义自己的事件池和事件顺序规则。例如，回声林地可出现迷路旅人、草药营地和史莱姆伏击；风蚀峡谷可出现流沙、商队补给和沙蝎伏击；沉船回廊可出现迷雾岔路、宝箱机关和水生精灵。事件池之间不互相共享随机结果。

创建探索时，服务端为整条路线生成并保存事件计划、权重抽取结果和需要玩家作出选择的节点。重启后继续读取已保存的路线，不重新抽取事件。路线长度和事件数量由静态数据限制，防止副本无法结束。

## 精灵对战与升级

副本遇敌复用精灵对战的战斗规则与回合命令，但使用 PvE 参与者：一侧是玩家当前宠物，另一侧是静态敌方精灵模板。伤害、治疗、魔力、速度先手、防御和技能合法性由同一领域规则计算；PvP 对手是另一名玩家，PvE 对手是敌人快照。

- 敌方精灵模板配置基础生命、魔力、攻击、防御、速度、等级成长和允许使用的技能。每个难度可指定敌人等级范围和首领模板。
- 遭遇战按回合行动。玩家沿用 `/精灵技能 <技能编号>`、`/精灵防御`；野生精灵由服务端 AI 根据当前 HP/MP 和技能效果选择行动。AI 规则固定且可复现，不调用 LLM。
- 普通敌人胜利后立即发放宠物经验；精英和首领可有更高经验奖励。奖励按敌人等级与副本难度配置，所有 XP 仍通过现有宠物升级规则结算，自动跨级并解锁等级技能。
- 重复通关可以继续刷经验。困难度与敌人等级应提高奖励效率，首领通关经验作为一次副本奖励；首期不设置每日次数和体力门槛。
- 战斗 HP/MP 在本次探索内继承，营地事件可以恢复。它们同步写回参战宠物，保证中断后继续探索时状态一致。探索结束、主动撤退或战败后回到城市；宠物保留实际剩余 HP/MP，需要使用城市休息服务恢复后才能重新进入副本。PvP 继续使用独立快照，不改变宠物存档状态。
- 精灵战败（HP 降为 0）立即结束当前探索，不奖励当前未胜利的敌人；此前已经结算的经验保留。主动撤退不返还已获得经验，也不发放首领通关奖励。
- 技能或宠物等级在一场战斗中采用开战快照；经验奖励生效后，下一场遭遇使用升级后的攻击、防御、生命、魔力和新技能。

城市休息服务首期提供简单恢复入口：`/宠物休息` 在无进行中探索时，将当前宠物 HP/MP 恢复至最大值。费用是否接入货币配置为城市服务数据；首期可配置免费，之后再由各城市定价。

## 探索流程

1. 玩家查看世界地图，逐级查看已开放国家、城市、副本和难度。
2. `/进入副本 <副本编号> <难度>` 校验城市解锁、难度开放、当前宠物存在且 HP 大于 0，并检查玩家没有未完成探索或 PvP 对战。
3. 服务端建立探索记录，冻结副本版本和路线事件计划，生成首个遭遇。
4. `/探索副本` 前进到下一个事件；若事件需要选择，服务返回选项并暂停等待 `/副本选择 <编号>`。
5. 遇到野生精灵时开启 PvE 战斗，玩家用精灵技能/防御命令行动；胜负后按事务写入宠物状态、经验、行动日志和探索游标。
6. 玩家可通过 `/副本状态` 查看当前地点、事件、HP/MP、探索进度、可执行命令；`/退出副本` 主动撤退。
7. 清除最终首领后记录通关、发放首领经验和通关奖励，计算城市/国家解锁，然后结束探索。

需要让副本活动与 PvP 互斥。开始副本前检查玩家无待处理或进行中的 PvP；创建 PvP 挑战时也检查玩家无进行中副本。两处检查必须在同一个 SQLite 写事务中完成，避免玩家同时进入两种战斗。

## 玩家命令

| 命令 | 行为 |
| --- | --- |
| `/世界地图` | 查看世界与当前开放进度 |
| `/国家 <编号或简称>` | 查看国家及其城市；国家支持拼音首字母或双字母简称 |
| `/城市 <编号>` | 查看城市、副本列表和休息服务 |
| `/副本 <编号>` | 查看副本故事、难度、推荐等级、事件和解锁条件 |
| `/进入副本 <副本编号> <难度>` | 开始一次探索 |
| `/探索副本` | 前进并触发下一节点 |
| `/副本选择 <选项编号>` | 选择当前事件分支 |
| `/副本状态` | 查看探索进度、宠物状态、当前事件和行动方 |
| `/退出副本` | 撤退并结算已获得的经验 |
| `/宠物休息` | 城市中恢复当前宠物 HP/MP |

同一平台的个人进度由发送者 ID 识别。副本状态和战斗命令只对探索者本人有效；第一阶段保持单人玩法，因此不需要群组投票或队伍成员权限。

## 资源结构

建议静态内容放在 `liuli/resources/world/`。其中 `world.json` 只描述唯一世界的名称、背景和默认起点，不维护可选世界列表：

- `world.json`：唯一世界的 ID、名称、背景和起始国家/城市。
- `countries.json`：国家、城市 ID 及解锁要求。
- `cities.json`：城市、副本列表、休息服务设置。
- `dungeons.json`：副本描述、难度、路线长度、事件权重、敌人池和解锁条件。
- `events.json`：事件文本、触发条件、选项和有限效果类型。
- `enemies.json`：野生精灵与首领属性、等级成长和可用技能。

加载时校验所有被引用的国家、城市、副本、事件、难度、敌人和技能 ID。对未知效果类型、非法权重、负属性、循环解锁条件、无终点路线或空敌人池的内容拒绝加载，并报告具体资源 ID。

## 持久化与事务

- `dungeon_runs`：每名玩家至多一个 `active` 记录，保存副本/难度/资源版本快照、路线计划、当前位置、当前事件、战斗快照、开始时间和最近更新时间。
- `dungeon_progress`：以 `platform_id + player_id + dungeon_id + difficulty_id` 为键记录通关次数、首次通关时间和解锁所需的最佳结果。
- `dungeon_run_events`：保存事件触发、选择和结果，支持续玩、复盘及防止同一事件重复结算。
- 玩家所有权、当前宠物校验、宠物 HP/MP、经验升级、技能解锁、事件游标和奖励必须在同一 SQLite 事务边界提交。
- 每个遭遇动作写入唯一动作流水；应用命令重试时根据 `run_id + encounter_id + round + player_id` 防止重复扣魔力、重复伤害和重复授予经验。
- 每次写入后更新探索状态；AstrBot 重启后玩家发送 `/副本状态` 或 `/探索副本` 即可恢复，不依赖常驻计时任务。

## 分层与实施顺序

- `liuli/domain/world.py`、`dungeon.py`：地图目录、难度、路线计划、事件状态机和解锁规则。
- `liuli/domain/combat.py`：从当前精灵对战规则抽取可供 PvP/PvE 共用的战斗参与者、行动结算和胜负规则。
- `liuli/application/dungeon_service.py`：地图浏览、进入、探索、事件选项、撤退、通关和 XP 奖励用例。
- `liuli/application/ports/dungeon_repository.py`：探索/进度/事件日志事务接口。
- `liuli/infrastructure/persistence/sqlite/dungeon_repository.py` 与新增迁移：持久化探索、关卡事件、战斗行动及通关进度。
- `main.py`：群聊/私聊命令适配和回复；只解析参数，不承载地图、事件或战斗逻辑。

实施建议先落地世界地图浏览和资源校验；随后完成一个国家、两个城市、三个副本的纵向流程；再抽取共用战斗核心，接入野生精灵与经验；最后补充事件选择、崩溃续玩、解锁链和城市恢复服务。内容数量通过资源扩充，不增加按副本写死的 Python 分支。
