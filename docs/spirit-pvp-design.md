# 玩家间精灵对战设计

## 目标与范围

精灵对战复用现有宠物实例、等级、属性和已装备技能。玩家在同一个群聊中发起挑战，双方同意后以回合制命令进行 1 对 1 对战。第一阶段提供友谊赛，不发货币、经验或宠物奖励，也不损伤宠物存档中的当前生命和魔力；排行榜和赛季奖励另行设计。

这里的“精灵”是对战场景中的宠物称呼，不新增第二类可拥有角色。每位玩家使用当前宠物参战。若玩家没有当前宠物，不能发起或接受挑战。

## 挑战与会话规则

- 仅允许在群聊发起和进行对战。战斗记录绑定 `platform_id + group_id`，双方必须来自同一平台、同一群组；私聊命令返回“请在群聊中使用”。
- `/精灵对战 @玩家` 发起挑战，目标收到群内挑战提示后使用 `/接受对战` 或 `/拒绝对战`。
- 不允许挑战自己、机器人或没有当前宠物的玩家。每位玩家同一时间只能有一场未结束对战；群里已有未结束对战时，也不受理新挑战。接受和拒绝命令在当前群组内匹配唯一一条待处理挑战。
- 挑战待接受时间为 60 秒。接受后每个操作回合限时 120 秒；超时后，超时一方判负。超时在下一次与该对战相关的命令到达时懒检查并结算；第一阶段不增加常驻轮询任务。如果需要在无人发消息时也主动通知，再单独接入可恢复的定时调度。
- 每场战斗限制最多 30 个完整回合。达到上限后按双方剩余生命比例判胜；仍相同则判平局。
- `/对战状态` 显示当前挑战/战斗、双方精灵、当前回合和可用操作。终态 battle 保留战绩和回合记录，但不再阻挡新挑战。

## 战斗规则

### 开局

接受挑战时，服务重新读取双方当前宠物和技能，验证宠物仍属于对应玩家且技能配置有效，再创建战斗快照。精灵的战斗生命和魔力从最大值开始，不读取、也不写回宠物档案中的当前生命/魔力。战斗中生命或魔力降至 0 只影响本场战斗。

接受时服务器根据双方速度计算先手概率，再随机决定并写入记录；速度相同时双方各有一半机会。之后双方交替行动。每个玩家只能操作自己这一侧；一回合每人最多提交一个行动。首个行动之后自动轮到另一方，双方都行动后回合数加一。

### 可用行动

| 命令 | 规则 |
| --- | --- |
| `/精灵技能 <技能编号>` | 使用当前精灵已装备技能；检查魔力足够，再扣除本场战斗快照中的魔力并应用效果 |
| `/精灵防御` | 本回合减少下一次受到的伤害；不消耗魔力 |
| `/精灵认输` | 主动结束当前对战并判负 |

普通攻击作为基础技能 `basic_attack`，始终可用、不消耗魔力。只有精灵当前装备的技能可以在对战中施放；已学但未装备的技能不可用。技能的 `target_type` 和 `effect_type` 决定合法目标和结算方式。第一阶段只支持 `single_enemy` + `damage` 与 `single_ally` + `heal`；增益、减益和其他目标/效果组合暂不参与对战，战斗快照会排除这类技能，待持续回合、叠加和清除规则明确后再扩展。

### 战斗数值

现有宠物模板只有生命/魔力成长和技能效果值。对战启用前，宠物模板需补充基础攻击、防御、速度，以及每级攻击、防御成长，均为非负整数；生命、魔力和攻击、防御都按宠物等级线性成长。第一阶段不根据聊天平台随机数或用户输入决定伤害。

建议结算公式：

```text
攻击力 = 模板基础攻击 + (等级 - 1) × 每级攻击成长
防御力 = 模板基础防御 + (等级 - 1) × 每级防御成长
技能伤害 = max(1, 技能效果值 + floor(攻击力 / 2) - 防御力)
防御姿态伤害 = max(1, floor(本次技能伤害 / 2))
治疗量 = min(技能效果值, 目标最大生命 - 目标当前生命)
```

数值必须由服务端在一个回合事务中计算。使用技能会扣除快照 MP；MP 不足时行动失败且不消耗回合。被治疗到满生命时仍正常消耗技能 MP 和本回合。伤害降至 0 HP 的一刻立刻终结战斗，不再接受该场的后续行动。

速度只用于开局先手概率。先手概率可按 `0.5 + 0.25 × (己方速度 - 对方速度) / max(己方速度 + 对方速度, 1)` 计算，因此较快一方的概率在 50% 至 75% 之间，速度相同时各为 50%。服务端生成随机结果并保存双方速度、概率和判定结果，方便复盘。之后严格交替，避免速度较高的一方连续出手。

防御姿态只对对手紧接着的这次行动有效：若该行动造成伤害，伤害减半（向下取整，至少为 1）；若该行动不造成伤害，姿态在该行动结束后消失，不延续到之后回合。

## 数据模型

宠物静态模板增加 `base_attack`、`attack_per_level`、`base_defense`、`defense_per_level`、`speed`。速度第一阶段不随等级成长。

新增 `spirit_battles`：

| 字段 | 用途 |
| --- | --- |
| `battle_id` | UUID 主键 |
| `platform_id`, `group_id` | 对战平台和来源群组 |
| `challenger_id`, `opponent_id` | 两名玩家的发送者 ID |
| `challenger_pet_id`, `opponent_pet_id` | 开战时选定的宠物 |
| `state` | `pending`、`active`、`finished`、`declined`、`expired`、`forfeit`、`draw` |
| `current_turn_player_id` | 当前可行动玩家 |
| `round_number` | 当前完整回合数 |
| `state_json` | 双方快照、HP/MP、已行动标志、防御状态、技能快照和先手结果 |
| `winner_id` | 胜方；平局或未结束时为空 |
| `created_at`, `updated_at`, `expires_at` | 创建、状态更新时间和当前阶段截止时间 |

新增 `spirit_battle_actions`：战斗 ID、回合号、玩家 ID、行动类型、技能 ID、服务端结算前后状态及创建时间。它用于回放、排错和防止同一玩家同回合重复出手；命令重试需要可识别的请求键，不能重复扣 MP 或重复结算伤害。

数据库至少增加以下约束与索引：

- 按 `platform_id + battle_id` 唯一定位对战。
- 按玩家查找其 `pending` 或 `active` 对战，并在事务中拒绝玩家同时参加两场对战；待处理挑战在每个群内最多一条，以保证接受/拒绝命令有唯一目标。
- `spirit_battle_actions` 对 `(battle_id, round_number, player_id)` 建唯一约束。
- 对战状态变化、行动流水插入和状态快照更新处于同一 SQLite 写事务。

战斗快照保存开战时的精灵昵称、模板数值、等级、装备技能定义和计算结果。宠物改名、等级变化或管理员更新技能目录，不改变已经进行中的战斗。终态快照和行动日志用于查询最终结果。

## 命令与消息

| 命令 | 行为 |
| --- | --- |
| `/精灵对战 @玩家` | 向同群玩家发挑战 |
| `/接受对战` | 接受自己收到的待处理挑战 |
| `/拒绝对战` | 拒绝待处理挑战 |
| `/对战状态` | 查看当前对战与自己可执行的操作 |
| `/精灵技能 <技能编号>` | 在自己的行动回合使用技能 |
| `/精灵防御` | 在自己的行动回合进入防御姿态 |
| `/精灵认输` | 认输并结束本场 |

每次行动只向来源群组发送一条结算摘要：行动者、技能、伤害/治疗、双方剩余 HP/MP、下一行动方。拒绝挑战、超时、认输、胜负和平局都应明确标记对战编号，避免同群多人时误认其他战斗结果。

挑战命令对目标玩家的提取必须使用 AstrBot 的消息实体/At 段，而不是从显示文本猜 ID；不同平台的 At 数据适配应留在 `main.py`。若适配器事件没有可验证的目标用户 ID，该平台不开放挑战命令。

## 分层和实现顺序

- `liuli/domain/spirit_battle.py`：战斗状态机、行动校验、伤害/治疗、防御、胜负和回合限制等纯规则。
- `liuli/application/spirit_battle_service.py`：挑战、接受、拒绝、行动、超时结算和消息摘要。
- `liuli/application/ports/spirit_battle_repository.py`：定义对战快照及行动日志的事务接口。
- `liuli/infrastructure/persistence/sqlite/spirit_battle_repository.py`：实现战斗状态、玩家占用检查、回合幂等和行动日志事务。
- `liuli/infrastructure/persistence/sqlite/migrations/`：新增战斗表和索引的迁移版本。
- `main.py`：解析群组身份和 At 段，注册指令并回复消息。

落地顺序：先补模板攻击/防御/速度与可战斗技能校验；再定义领域状态机及确定性数值公式；然后新增事务仓储和挑战/对战命令；最后验证重复命令、双人同时接受、超时结算、跨群/跨玩家操作、胜负终结和重启后恢复。排行榜、排位分、奖励、组队战和跨群匹配另行设计。
